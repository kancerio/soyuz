# API Contracts for AI Service

Этот документ фиксирует форматы запросов и ответов для эндпоинтов AI-сервиса.  
Все эндпоинты на данный момент возвращают **заглушки (mock)**, но формат останется неизменным при добавлении реальной логики.


## 1. Перевод текста – `/translate` (POST)

### Описание
Переводит текст с одного языка на другой.

### Запрос
- **URL:** `http://localhost:8000/translate`
- **Метод:** `POST`
- **Content-Type:** `application/json`

**Поля JSON:**
| Поле         | Тип    | Обязательное | Описание                              |
|--------------|--------|--------------|---------------------------------------|
| `text`       | string | да           | Исходный текст                        |
| `source_lang`| string | да           | Код языка оригинала (например, `en`)  |
| `target_lang`| string | да           | Код языка перевода (например, `ru`)   |

**Пример запроса:**
```json
{
  "text": "Hello, how are you?",
  "source_lang": "en",
  "target_lang": "ru"
}
```

### Ответ (200 OK)
```json
{
  "original_text": "Hello, how are you?",
  "translated_text": "[переведено с en на ru]: Hello, how are you?",
  "source_lang": "en",
  "target_lang": "ru"
}
```

### Ошибки
- `422 Unprocessable Entity` – неверный формат JSON или отсутствуют обязательные поля.

### Пример вызова через `curl`
```bash
curl -X POST http://localhost:8000/translate \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello","source_lang":"en","target_lang":"ru"}'
```

## 2. Распознавание речи (STT) – `/stt` (POST)

### Описание
Преобразует аудиофайл (голосовое сообщение) в текст и возвращает краткое резюме.

### Запрос
- **URL:** `http://localhost:8000/stt`
- **Метод:** `POST`
- **Content-Type:** `multipart/form-data`

**Поля формы:**
| Поле       | Тип        | Обязательное | Описание                                       |
|------------|------------|--------------|------------------------------------------------|
| `audio`    | файл       | да           | Аудиофайл (wav, mp3, ogg)                      |
| `language` | string     | нет          | Язык распознавания (по умолчанию `ru`)         |

### Ответ (200 OK)
```json
{
  "recognized_text": "Привет, как дела?",
  "summary": "Краткое содержание: приветствие",
  "language": "ru"
}
```

### Ошибки
- `422 Unprocessable Entity` – файл не загружен или формат не поддерживается.

### Пример вызова через `curl`
```bash
curl -X POST http://localhost:8000/stt \
  -F "audio=@/path/to/voice.wav" \
  -F "language=ru"
```

## 3. ИИ-помощник – `/assist` (POST)

### Описание
Выполняет действия над текстом: сокращение, изменение тона, генерация подсказки.

### Запрос
- **URL:** `http://localhost:8000/assist`
- **Метод:** `POST`
- **Content-Type:** `application/json`

**Поля JSON:**
| Поле       | Тип    | Обязательное | Описание                                            |
|------------|--------|--------------|-----------------------------------------------------|
| `prompt`   | string | да           | Текст для обработки                                 |
| `context`  | string | нет          | Контекст чата (может повлиять на результат)         |
| `action`   | string | да           | Действие: `shorten`, `change_tone`, `suggest`       |

**Допустимые значения `action`:**
- `shorten` – сократить текст, оставив суть
- `change_tone` – изменить тон (например, сделать вежливее)
- `suggest` – предложить продолжение или ответ

**Пример запроса (сокращение):**
```json
{
  "prompt": "Это очень длинное сообщение, которое нужно сократить до нескольких слов",
  "action": "shorten"
}
```

**Ответ (200 OK):**
```json
{
  "result": "Кратко: Это очень длинное сообщение, которое нужно сократить до нескольких слов..."
}
```

**Пример запроса (смена тона):**
```json
{
  "prompt": "Ты глупый",
  "action": "change_tone"
}
```
**Ответ:**
```json
{
  "result": "(Сменили тон) Ты глупый"
}
```

### Ошибки
- `422 Unprocessable Entity` – неверный `action` или отсутствует `prompt`.

### Пример вызова через `curl`
```bash
curl -X POST http://localhost:8000/assist \
  -H "Content-Type: application/json" \
  -d '{"prompt":"This is a long text","action":"shorten"}'
```

## 4. ИИ-секретарь – `/secretary` (POST)

### Описание
Создаёт встречи, напоминания или подводит итоги обсуждения.

### Запрос
- **URL:** `http://localhost:8000/secretary`
- **Метод:** `POST`
- **Content-Type:** `application/json`

**Поля JSON:**
| Поле       | Тип    | Обязательное | Описание                                                     |
|------------|--------|--------------|--------------------------------------------------------------|
| `action`   | string | да           | `create_meeting`, `reminder`, `summary`                      |
| `details`  | string | да           | Детали (например, время встречи или текст для итогов)        |

**Пример запроса (создание встречи):**
```json
{
  "action": "create_meeting",
  "details": "Встреча с командой завтра в 10:00"
}
```
**Ответ:**
```json
{
  "message": "Встреча создана (заглушка)",
  "data": {
    "event_id": "123",
    "datetime": "2025-04-03T10:00:00"
  }
}
```

**Пример запроса (напоминание):**
```json
{
  "action": "reminder",
  "details": "Позвонить клиенту"
}
```
**Ответ:**
```json
{
  "message": "Напоминание установлено",
  "data": {
    "reminder_id": "456"
  }
}
```

**Пример запроса (итоги):**
```json
{
  "action": "summary",
  "details": "Обсудили бюджет и сроки"
}
```
**Ответ:**
```json
{
  "message": "Итоги обсуждения: Обсудили бюджет и сроки",
  "data": null
}
```

## 5. Анализ документов – `/document-analysis` (POST)

### Описание
Извлекает ключевую информацию из загруженного документа (PDF, DOCX и т.п.).

### Запрос
- **URL:** `http://localhost:8000/document-analysis`
- **Метод:** `POST`
- **Content-Type:** `multipart/form-data`

**Поля формы:**
| Поле             | Тип    | Обязательное | Описание                          |
|------------------|--------|--------------|-----------------------------------|
| `file`           | файл   | да           | Документ (PDF, DOCX, TXT)         |
| `extract_fields` | string | нет          | Какие поля извлечь (через запятую)|

**Пример запроса:**
```bash
curl -X POST http://localhost:8000/document-analysis \
  -F "file=@/path/to/document.pdf" \
  -F "extract_fields=реквизиты,суть"
```

**Ответ (200 OK):**
#json
{
  "filename": "document.pdf",
  "summary": "Это тестовый анализ документа. Извлечены ключевые слова.",
  "fields": {
    "реквизиты": "123-456",
    "суть": "пример документа"
  },
  "classification": "договор"
}

## Общие замечания

- **Базовая URL:** `http://localhost:8000` (при локальном запуске)
- **Swagger-документация:** `http://localhost:8000/docs`
- **Все ответы в случае ошибки** возвращают HTTP-код 4xx или 5xx с JSON-телом:
  #json
  {
    "detail": "Описание ошибки"
  }

- **Формат дат и времени:** в ответах секретаря используется ISO 8601 (`YYYY-MM-DDTHH:MM:SS`).

- **Коды языков** для перевода и STT: используются двухбуквенные коды (`en`, `ru`, `fr`, `de` и т.д.).

- **Пока все эндпоинты возвращают заглушки**, но контракт останется неизменным при добавлении реальных моделей или внешних API.
