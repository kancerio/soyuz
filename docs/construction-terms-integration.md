# Строительные термины: AI-контракт и задачи команд

Документ фиксирует границы работы AI / DevOps / QA и интеграционные задачи
Frontend и Backend.

## Реализуемая AI-операция

AI-сервис предоставляет `POST /construction-terms`.

Запрос:

```json
{
  "text": "Нужно проверить армирование стены.",
  "source_language": "ru",
  "response_language": "en",
  "country_code": "RU",
  "max_terms": 5
}
```

- `text`: непустое сообщение, максимум 5 000 символов.
- `source_language` и `response_language`: один из 27 кодов из
  [`language_codes.md`](language_codes.md). `auto` для этих полей не принимается.
- `country_code`: двухбуквенный ISO 3166-1 alpha-2 код страны отправителя.
- `max_terms`: от 1 до 10, по умолчанию 5.

Успешный real-ответ:

```json
{
  "terms": [
    {
      "term": "армирование",
      "start": 16,
      "end": 27,
      "definition": "Steel reinforcement used to strengthen a concrete structure.",
      "country_code": "RU",
      "source_title": "Армирование",
      "source_url": "https://ru.wikipedia.org/wiki/Армирование",
      "source_language": "ru"
    }
  ],
  "source_language": "ru",
  "response_language": "en",
  "country_code": "RU",
  "provider": "lmstudio",
  "mock": false,
  "correlation_id": "..."
}
```

`start` и `end` — нулевые смещения UTF-16, `end` не включается. Это соответствует
индексам строк JavaScript, поэтому Frontend может обернуть найденный фрагмент в
ссылку без повторного поиска слова. Ответ содержит только термины, которые
модель нашла в исходном сообщении, и для которых найден источник и создано
объяснение. Не найденные или не процитированные результаты не показываются.

В mock-режиме сервис возвращает `terms: []`, `provider: "mock"`, `mock: true`.
Такой ответ проверяет контракт, но не обнаруживает строительные термины.

Ошибки: 422 — валидация; 502 — некорректный ответ AI или ошибка поиска; 503 —
AI/источник недоступен; 504 — тайм-аут. Клиенту следует сохранить исходное
сообщение и показать возможность повторить анализ.

## Поиск и ограничения качества

В real-режиме модель извлекает точные подстроки из текста. Затем AI-сервис
ищет статью через публичный Wikimedia REST API на языке исходного сообщения,
передавая код страны как контекст для уточнения поиска. Модель кратко
переформулирует выдержку найденной статьи на языке интерфейса. Ссылка строится
на домене выбранной языковой Википедии, а не генерируется моделью. Описание
эндпоинтов: [MediaWiki REST API: поиск страниц](https://www.mediawiki.org/wiki/API:REST_API/Reference/en#Search_pages),
[начало работы](https://www.mediawiki.org/wiki/API:REST_API/Get_started).

Это MVP на базе Wikipedia, включая РуВики. Код страны помогает задать контекст,
но сам по себе не подтверждает, что статья относится к нормам и практике
конкретной юрисдикции. Wikipedia также не является официальным нормативным
источником. Для юридически или технически значимых требований следующая
итерация должна добавить проверенный поиск по официальным строительным
нормативам и каталогу доверенных доменов каждой страны. UI должен показывать,
что текущая ссылка ведёт на Wikipedia.

Контент может быть неоднозначным, жаргонным или ошибочным. AI-объяснение —
краткий пересказ выдержки, а не экспертное заключение; пользователю всегда
доступна исходная ссылка. Mock не подходит для оценки обнаружения терминов,
качества перевода или полноты источников.

## Задачи Backend

1. Расширить `TranslateDto` и валидацию `preferred_language` до 27 кодов из
   [`language_codes.md`](language_codes.md), синхронизировать enum/типы API и
   OpenAPI. Сейчас AI-сервис знает больше языков, чем текущий Backend DTO.
2. Добавить JWT-защищённый маршрут, например
   `POST /messages/:messageId/construction-terms`. Проверять членство
   пользователя в чате и брать текст, страну и язык отправителя из сохранённого
   сообщения/профиля, а не доверять переданным клиентом данным.
3. Передавать в AI-сервис `text`, `source_language`, `response_language` текущего
   пользователя и `country_code` отправителя. Не запускать отдельный запрос на
   каждый термин.
4. Обрабатывать ответ как отдельную функцию сообщения. Рекомендуемый поток:
   фоновая задача после сохранения сообщения → событие
   `message.construction_terms` со статусом `completed`/`failed` → событие
   повторно при открытии истории либо endpoint по запросу. Не задерживать
   отправку самого сообщения из-за AI или Wikimedia.
5. Возвращать Frontend массив терминов без переименования `start`/`end` и
   источника; пробрасывать ошибки 503/504/502 как статус анализа, сохраняя
   доступность сообщения.
6. При необходимости добавить поля/хранилище для статуса анализа. Если результат
   не сохраняется, определить кэширование по message id + языку интерфейса +
   стране и ограничить повторные вызовы.

## Задачи Frontend

1. Синхронизировать выбор языка приложения с 27 кодами и отправлять текущий
   `preferred_language` как `response_language` через Backend.
2. Отрисовать термины поверх исходного текста по UTF-16 диапазонам
   `[start, end)`. Не менять сохранённый текст сообщения; каждое совпадение
   должно быть доступной клавиатурой ссылкой/кнопкой.
3. По нажатию показывать небольшую карточку: термин, объяснение на языке
   интерфейса, код страны отправителя, подпись «Wikipedia» и действие
   «Подробнее» с `source_url`. Открывать внешнюю ссылку с безопасными атрибутами.
4. Показывать состояния обработки, отсутствие найденных терминов, сбой поиска
   и повторный запуск. В mock-режиме не показывать mock-маркеры как найденные
   реальные термины.
5. Проверить длинные сообщения, повтор одного термина, разные языки, emoji перед
   ссылкой, мобильную ширину, доступность и направление текста RTL для арабского.

## Задачи AI / DevOps / QA

- Реализованы контракт, real/mock ветки, извлечение точных подстрок, ссылка на
  найденную статью, краткое объяснение на языке интерфейса, корреляционный ID и
  обработка ошибок источника/модели.
- Добавлены модульные тесты на mock, источники, пропуск неподтверждённого
  результата, UTF-16 смещения, языки, тайм-ауты и недоступность провайдеров.
- AI-тесты уже входят в `.github/workflows/ci.yml`; дополнительных секретов для
  Wikimedia REST API не требуется. Для вызовов источника нужен исходящий HTTPS.
- После интеграции Backend требуется отдельный real smoke на локальной модели и
  проверка страны/языка на реальных примерах. CI mock-тесты не являются
  доказательством реального качества модели или полноты данных.
